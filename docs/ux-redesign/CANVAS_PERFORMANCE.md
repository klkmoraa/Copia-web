# Canvas performance note — Phase 7

## Measurement

Reference fixture: Pórtico de ejemplo, 1536 × 960, development build in system Chrome, 24 alternating wheel-zoom inputs at the canvas center.

| Metric | Before Phase 7 | After Phase 7 |
| --- | ---: | ---: |
| Average animation frame | 16.604 ms | 16.666 ms |
| Post-change p95 frame | — | 16.700 ms |
| Post-change maximum frame | — | 16.800 ms |

The browser-protocol command duration varied between runs and is intentionally excluded from comparison; frame cadence is the stable signal. The post-change result remained at the display cadence with no long frame in the captured window.

## Hot paths and safeguards

- Camera changes remain in `cameraRef` and commit through one requestAnimationFrame batch.
- Wheel and pinch calculations remain independent of React component-library controls.
- SVG geometry is not regenerated by `CanvasChrome`; only scale text updates with camera state.
- Label placement is deterministic and bounded by visible candidates and safe-zone attempts.
- The model, load, result, and diagnostic groups remain layer-gated.

Production output moved from 247.15 kB to 250.91 kB raw for the lazy WorkspaceShell JavaScript chunk (+3.76 kB), while its gzip size moved from 67.25 kB to 68.46 kB (+1.21 kB). No engine or worker chunk grew.
